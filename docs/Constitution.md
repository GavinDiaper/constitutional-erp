# Constitution Design 
### Subsystems × Design Principles

| **Subsystem**        | **1. AI Drives Execution**                                                                 | **2. Humans Govern**                                                                                   | **3. Mesh Is the Constitutional Truth**                                                                                          | **4. ERP Is a Projection**                                                                 | **5. UX Is Process First**                                                                                 |
|----------------------|--------------------------------------------------------------------------------------------|--------------------------------------------------------------------------------------------------------|-----------------------------------------------------------------------------------------------------------------------------------|-----------------------------------------------------------------------------------------------------------|-----------------------------------------------------------------------------------------------------------|
| **navigator-ai**     | Proposes actions, navigates process graph, simulates outcomes, explains decisions.         | Enforces authority tiers via governance metadata; surfaces approvals/choices to humans.               | Orchestrates Mesh via Integration Hub; consumes Mesh events as ground truth for reasoning.                                       | Treats ERP as opaque executor behind Mesh; never binds to ERP specifics.                                  | Drives “what is possible next” for Canvas/REPL; no roles/menus, only next actions.                        |
| **navigator REPL**   | Developer cockpit to invoke propose/simulate/decide/execute flows step-by-step.           | Lets humans inspect, override, and replay decisions; manual control over execution.                   | Shows canonical events and Mesh outcomes for each command; used to validate constitutional behaviour.                            | Lets devs see ERP projections indirectly via canonical responses.                                         | Process-first CLI: commands are transitions on process graphs, not module/role centric.                  |
| **process-graph**    | Defines the graph Navigator traverses; encodes allowed transitions and simulation hints.  | Encodes where approvals are required, risk tiers, and governance hooks.                               | Canonical representation of process state; aligns with Mesh event semantics.                                                     | Abstracts ERP workflows into canonical lifecycles.                                                         | The backbone of “what is possible next”; no roles/menus, only state → transitions.                        |
| **integration-hub**  | AI-facing constitutional API; Navigator calls Hub, not Mesh/ERP directly.                 | Enforces governance at the boundary (risk, authority, SoD) before actions reach Mesh.                 | Publishes hypermedia + MCP over Mesh/ERP; uses Mesh events as the constitutional record surface.                                 | Presents ERP as a set of canonical commands; hides vendor specifics.                                      | Hypermedia responses define next possible actions; no module/role navigation.                             |
| **mesh-gateway**     | Executes the actions chosen by AI/humans; no independent “will”, just execution.          | Enforces technical constraints (idempotency, retries) but defers business governance to Hub.          | Executes constitutional actions and emits canonical events; its event log is the execution truth.                                | Maps canonical commands to ERP APIs; ERP is just an implementation detail behind Mesh.                    | Invisible to UX; its behaviour is reflected as state changes and events in process-first views.           |
| **event-processor**  | Feeds Navigator with event history for simulation and explanation (via Hub/CEP).          | Supports human-triggered rollback/replay by driving event-based reconstruction.                       | Stores and replays canonical events; basis for “Mesh is the constitutional truth” and state reconstruction.                      | Rebuilds ERP state from events when needed; ERP becomes a projection of the event log.                    | Powers timelines and histories in UX; users see flows as event sequences, not screens/modules.            |
| **foundation-erp**   | No AI inside; responds to canonical commands coming from Mesh/Hub/Navigator.              | Governance is external; ERP executes only what has been authorised upstream.                          | Emits canonical events that Mesh/CEP treat as part of the constitutional record.                                                 | Pure projection: executes commands, posts transactions, can be replaced/rebuilt without changing canon.   | Not user-facing in the constitutional UX; its structures are surfaced as canonical state, not ERP screens.|
| **authority-engine** | Provides authority tiers and trust scores that Navigator uses in decision-making.         | Core to “Humans Govern”: models earned authority, revocation, and domain-specific trust.              | Its evaluations are recorded as part of governance events; contributes to constitutional truth about “who could do what, when”. | ERP-agnostic; authority is over canonical actions, not ERP roles.                                         | Feeds UX with “who may approve/execute” at each step instead of static roles/menus.                       |
| **governance-engine**| Constrains what AI can propose/execute; evaluates risk, SoD, thresholds.                  | Encodes the constitutional rules humans define; approvals, limits, constraints.                       | Its decisions are logged as governance events; part of the constitutional record alongside Mesh events.                         | Rules apply at canonical level; ERP workflows are downstream projections of these constraints.            | UX shows governance outcomes inline with process (e.g. “needs T3 approval”), not as separate modules.     |
| **integration-hub**  | (already above; key AI boundary)                                                          | (already above)                                                                                       | (already above)                                                                                                                  | (already above)                                                                                           | (already above)                                                                                           |
| **navigator UI (future Canvas)** | Visual host for Navigator proposals, simulations, explanations.                         | Humans approve, correct, and trigger rollback/replay from here.                                       | Shows canonical state + event history; visualises Mesh truth and governance decisions.                                           | Shows ERP as derived facts (balances, documents) rather than ERP-native screens.                          | Pure process-first UX: state views + “what is possible next”; no roles, menus, or modules.               |
